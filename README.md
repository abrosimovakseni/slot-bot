# SLOT — очередь на консультации к куратору

Telegram-бот [@SLOT_hse_bot](https://t.me/SLOT_hse_bot) для записи студентов на
консультации к куратору. Запись открывается автоматически каждую среду и
пятницу в 09:30 (Europe/Moscow), за час до пары в 10:30. Очередь учитывает
индивидуальный статус каждого студента (`PRIORITY` / `RESTRICTED`), который
чередуется после каждой состоявшейся записи — подробности ниже.

## Как это устроено (коротко, без кода)

- **Расписание** задано в одном месте — `slot_bot/config.py`. Если куратор
  когда-нибудь изменит день/время пары, достаточно поправить несколько строк
  в этом файле.
- **Вся важная информация хранится в PostgreSQL**, а не в памяти процесса:
  список студентов, история консультаций, кто на каком месте, чей сейчас
  статус PRIORITY/RESTRICTED. Поэтому перезапуск бота (например, после
  деплоя на Railway) ничего не теряет и не запускает никакие действия
  повторно.
- **Очередь** пересчитывается на лету по простому правилу: места 1-5
  зарезервированы за студентами со статусом PRIORITY (в порядке записи),
  все остальные — начиная с места 6, тоже строго в порядке записи, статус
  там уже не даёт преимущества.
- **Статус** каждого студента переключается ровно один раз за
  консультацию — но только если студент реально остался в очереди до
  завершения консультации (отменённая запись не считается участием).
  Пропущенные консультации статус не меняют.
- **Идемпотентность.** Открытие записи и подведение итогов консультации
  устроены так, что даже если Railway перезапустит бота в середине процесса,
  ни рассылка, ни переключение статусов не произойдут дважды — это
  проверено автоматическими тестами (в том числе с настоящей конкурентной
  нагрузкой на PostgreSQL).

## Структура проекта

```
slot_bot/
  config.py              расписание, размер приоритетного блока, env-переменные
  models.py               таблицы PostgreSQL (SQLAlchemy)
  db.py                    подключение к базе
  time_utils.py            расчёт дат/времени по расписанию (Europe/Moscow)
  exceptions.py            типы ожидаемых ошибок
  services/
    users.py               регистрация, профиль
    queue.py                запись, отмена, расчёт очереди (ядро логики)
    consultations.py        открытие/закрытие консультаций, идемпотентность
  bot/
    app.py                  сборка Telegram-приложения и расписания задач
    handlers_start.py       /start и регистрация
    handlers_profile.py     профиль, смена имени
    handlers_queue.py       запись/отмена/очередь/моё место
    notifications.py        рассылки с обработкой заблокировавших бота
    keyboards.py, texts.py  кнопки и тексты сообщений
  main.py                   точка входа
tests/                      автоматические тесты (см. ниже)
```

## Локальный запуск

Нужен Python 3.11+ и запущенный PostgreSQL.

1. Создайте виртуальное окружение и установите зависимости:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements-dev.txt
   ```

2. Скопируйте `.env.example` в `.env` и заполните значения (см. раздел
   "Переменные окружения" ниже):

   ```bash
   cp .env.example .env
   ```

3. Убедитесь, что PostgreSQL запущен и создана база данных, указанная в
   `DATABASE_URL` (например `slot_dev`). Таблицы бот создаёт сам при
   старте — вручную ничего создавать не нужно.

4. Запустите бота:

   ```bash
   set -a; source .env; set +a
   python -m slot_bot.main
   ```

Бот сам создаст нужные таблицы, восстановит расписание и начнёт отвечать в
Telegram.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от @BotFather |
| `DATABASE_URL` | да | Строка подключения к PostgreSQL |
| `ADMIN_ID` | нет | Ваш Telegram user_id — бот пришлёт сообщение при неожиданной ошибке |
| `RECONCILE_INTERVAL_SECONDS` | нет | Как часто (в секундах) бот перепроверяет состояние базы на всякий случай. По умолчанию 900 (15 минут) |

**Токен бота никогда не должен оказаться в коде или в GitHub.** Он живёт
только в `.env` локально (файл в `.gitignore`, не коммитится) и в
переменных окружения сервиса на Railway.

## Тесты

```bash
source .venv/bin/activate
python -m pytest -q
```

Тесты запускаются против настоящего локального PostgreSQL (не SQLite) —
это важно, потому что часть тестов специально проверяет поведение под
реальной конкурентной нагрузкой (блокировки строк, уникальные ограничения,
атомарные UPDATE ... WHERE ... IS NULL). По умолчанию тесты используют базу
`postgresql://postgres:postgres@localhost:5432/slot_test` — при
необходимости адрес можно переопределить переменной `TEST_DATABASE_URL`.

Тесты покрывают все 21 сценарий, перечисленный в задании (порядок очереди
1-5/6+, приоритет/ограничение и их чередование, отмена записи и пересчёт,
одновременные запросы на запись от одного и от разных пользователей,
идемпотентность двойного завершения консультации, восстановление после
перезапуска, расписание среда/пятница 09:30) — имена тестов в файлах
`tests/test_*.py` соответствуют этим сценариям.

## Deployment на Railway

1. Запушьте проект в GitHub (см. ниже).
2. На [railway.app](https://railway.app) создайте новый проект из этого
   GitHub-репозитория.
3. Добавьте в проект плагин **PostgreSQL** — Railway сам создаст базу и
   переменную `DATABASE_URL`; в настройках сервиса бота сошлитесь на неё
   как `${{Postgres.DATABASE_URL}}` (Railway подставит их автоматически,
   если сервисы в одном проекте).
4. В переменных окружения сервиса бота задайте `BOT_TOKEN` (и, по желанию,
   `ADMIN_ID`).
5. Стартовая команда уже задана в `railway.json` (`python -m slot_bot.main`)
   — ничего дополнительно настраивать не нужно.
6. Railway задеплоит сервис как фоновый процесс (без веб-порта) и будет
   держать его запущенным 24/7, перезапуская при сбоях
   (`restartPolicyType: ON_FAILURE` уже настроено).

Бот не требует, чтобы ваш компьютер или терминал с Claude Code были
постоянно открыты — после деплоя на Railway он работает независимо.

## Известные ограничения (сделано намеренно, чтобы не усложнять)

- Если процесс упадёт **прямо посреди** рассылки уведомления об открытии
  записи, часть студентов может не получить сообщение в этот раз (сама
  запись при этом не откроется повторно и не будет дублироваться — это
  проверено тестами). Для курса из нескольких десятков студентов и
  быстрой отправки сообщений через Telegram API это очень маловероятный
  сценарий.
- Если бот был выключен всю среду/пятницу целиком, "задним числом" эта
  консультация не создаётся при следующем запуске — бот ждёт следующую
  дату по расписанию. Это осознанное решение: создавать консультацию,
  на которую студенты физически не могли успеть записаться, было бы
  бессмысленно.
